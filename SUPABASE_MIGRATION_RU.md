# Supabase Free: подключение и безопасный перенос H2

## Текущий статус

Проект `zerdeai-shared` создан в бесплатной организации `zerde ai`, регион `ap-south-1`. В облаке есть приватная таблица `zerdeai.records(kind,id,body JSONB)`. На ней включён и принудительно включён RLS; таблица не выдана ролям `anon` и `authenticated` и находится вне публичной API-схемы. Доступ выдаётся только роли `zerdeai_backend`. Обычная проверка Supabase подтвердила создание таблицы, а тестовая запись была прочитана и удалена.

Один перенос с компьютера владельца уже выполнен после закрытия ZerdeAI: записи из проверенной копии H2 импортированы в Supabase, содержимое сверено обратно с копией, ошибки связей не найдены. Оригинальная H2-база не менялась; проверенная копия и JSON backup лежат отдельно от исходников/ZIP и содержат личные учебные данные. Не загружайте их в GitHub. Не запускайте `--Apply` повторно на этом проекте: он уже не пустой и импортёр остановится.

Приложение поддерживает JDBC-подключение к PostgreSQL. Отдельная login-роль и её пароль ещё не настроены, поэтому обычный запуск установленного приложения продолжает использовать H2. При явной конфигурации Supabase и ошибке соединения приложение завершает запуск с ошибкой и **не переключается** на H2. После создания отдельной роли запуск выполняется через `START_SUPABASE.ps1`.

## Ограничения бесплатного тарифа

Supabase Free не требует платной подписки, но имеет квоты и может приостанавливать неактивные проекты. Перед публикацией сверяйте [актуальные лимиты тарифа](https://supabase.com/pricing) и [правила паузы/возобновления](https://supabase.com/docs/guides/platform/going-into-prod#pausing-and-restoring-projects). Этот проект не использует платные дополнения.

## Подготовка отдельной роли сервера

Не используйте `service_role`, `anon` key или пароль `postgres` из браузера, WebView, исходников либо установщика. На сервере приложения нужны только данные отдельной роли. Откройте Supabase Dashboard → SQL Editor и создайте отдельную роль, заменив длинный пароль собственным случайным значением:

```sql
CREATE ROLE zerdeai_app LOGIN PASSWORD 'ЗАМЕНИТЕ_СЛУЧАЙНЫМ_ПАРОЛЕМ' IN ROLE zerdeai_backend;
```

Пароль не включайте в проект, скриншоты, GitHub, ZIP или EXE. Если пароль уже попал в SQL history, смените его перед запуском приложения. Для пула используйте **Session pooler**, а не transaction pooler, поскольку JDBC может применять prepared statements. Скопируйте URL из Dashboard → Connect, замените начало `postgresql://` на `jdbc:postgresql://` и добавьте `sslmode=verify-full` в query string. Логин для pooler обычно задаётся как `<имя_роли>.<project_ref>`; используйте значение, которое показывает ваш Dashboard.

## Подключение приложения

Запустите `START_SUPABASE.ps1` на доверенном компьютере-сервере. Введите JDBC URL и имя роли, пароль вводится скрыто. Скрипт передаёт значения только процессу ZerdeAI и очищает переменные после выхода; постоянный файл с паролем не создаётся. Если проверка соединения, таблицы или прав не проходит, приложение покажет ошибку. До импорта данных база не включится.

Студенческие компьютеры продолжают подключаться через `START_WIFI.bat`/`CONNECT.bat` и серверный API с проверкой сессии и роли. PostgreSQL URL и пароль клиентам не передаются.

## Перенос H2

Не включайте Supabase для существующей группы до полного импорта и проверки. Сначала:

1. Остановите сервер ZerdeAI и скопируйте `%USERPROFILE%\EduTestSuite2` в отдельную резервную папку. Не запускайте миграцию поверх единственной копии.
2. Проверяйте копию H2, а не живую пользовательскую базу. Сформируйте JSON backup штатной функцией ZerdeAI и посчитайте SHA-256 файлов.
3. В проекте задайте полный каталог H2 (по умолчанию `%USERPROFILE%\EduTestSuite2`) и отдельный файл backup. При закрытой ZerdeAI выполните предварительную проверку и экспорт:

   ```powershell
   powershell -ExecutionPolicy Bypass -File scripts\supabase-migration.ps1 -Action Export -BackupFile "C:\Backups\zerdeai.migration-backup.json"
   ```

   Утилита проверит JSON, ID, активного преподавателя и связи групп, заданий, попыток, чатов, курсов и прогресса. Она покажет количества по всем типам строк, включая локальные записи панели администратора. Резервная копия создаётся только новым файлом, без перезаписи.
4. Проверьте отчёт и храните JSON только локально: он содержит хеши паролей и переписку. Не загружайте его в GitHub/ZIP.
5. Для импорта выполните отдельную команду с тем же каталогом и backup. Введите `IMPORT`, URL Session pooler, имя отдельной роли и её пароль:

   ```powershell
   powershell -ExecutionPolicy Bypass -File scripts\supabase-migration.ps1 -Action Apply -BackupFile "C:\Backups\zerdeai.migration-backup.json"
   ```

   Импорт разрешён только в пустую облачную таблицу, использует INSERT без перезаписи, проверяет строки/количества и перечитывает их после нового JDBC-соединения. При ошибке вставка откатывается; H2 остаётся без изменений.
6. Только после успешного отчёта переключайте доверенный сервер на Supabase. Сохраните H2 и JSON backup на время приёмки. Не включайте запись сразу в две базы.

Первичный перенос данных этой установки завершён и повторно сверен с проверенной копией H2. Java JDBC запуск и повторное чтение из самого ZerdeAI пока не проверялись, поскольку отдельная login-роль и пароль не созданы. После настройки роли выполните `START_SUPABASE.ps1`; не повторяйте импорт в этот уже заполненный проект.
